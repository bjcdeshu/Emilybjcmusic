This contract coordinates the two Hermes implementation workers. `packages/shared/src/index.ts` is the wire-type source. All responses use `ApiResponse<T>`; failures also use meaningful HTTP status codes. No provider cookies, keys, passwords or raw secret-bearing errors appear in JSON or logs.

## Endpoints

- `GET /api/health` → `HealthResponse`, minimal unauthenticated health.
- `GET /api/session` → `AuthSession`; no sensitive session/token content.
- `POST /api/login` `{ password: string }` → `AuthSession`, sets HttpOnly session cookie.
- `POST /api/logout` → `AuthSession`, invalidates cookie/session.
- `GET /api/setup` → `SetupStatus`, protected; booleans/safe identity only.
- `GET /api/settings` and `PATCH /api/settings` partial `RadioSettings` → `RadioSettings`, protected; default Mandarin female Xiaoxiao, DJ on, modest volume. Voice determines `hostLanguage: zh|en`; a language-only patch selects that language's default voice, conflicting explicit voice/language returns400. Existing owner settings migrate once to Chinese, retaining quiet/volume/mood/discovery; future explicit English selection survives restart.
- `POST /api/music/login/qr` → `MusicQrSession`, protected; QR generated by the configured authorized NetEase adapter.
- `GET /api/music/login/qr/:key` → `MusicQrPollResponse`, protected; owner-scoped ticket, short expiry, never returns provider cookies.
- `POST /api/music/disconnect` → `SetupStatus`, protected.
- `GET /api/music/playlists` → `PlaylistResponse`, protected.
- `GET /api/music/search?q=...` → `MusicSearchResponse`, protected, bounded input.
- `GET /api/music/lyrics/:id` → `LyricsResponse`, owner-protected/private-no-store/provider-read rate90 per minute shared with setup/search/library. Valid ID and known real catalogue required; verifies the owner's connection. Only fixed adapter POST `/lyric`; no alternate source, public lyrics or storage. Response `{trackId,status: synced|plain|instrumental|missing,lines:[{timeMs,text}],text?}` uses bounded real LRC (100k chars/2000 rows, multi-tags/fractions/offset/blank lines), not invented timing; service/malformed/oversize failure remains honest502. Fetching lyrics does not affect transport/history. Browser holds ≤12 results in volatile component memory, aborts stale requests on switch/unmount, clears on disconnect/logout; private API stays outside SW cache.
- `POST /api/programme` body `ProgrammeRequest` → `ProgrammeResponse`, protected. Assemble playable real catalogue candidates; validate model-selected IDs against those candidates. Optional `roaming:true` with playlist source continues in that SAME owner playlist; batch max12. `ordered:true` for confirmed explicit tracks preserves supplied order (rights rechecked), avoiding a second model reorder. With no model, return the honest `selectionSource: playlist` and a warning, not simulated AI success. With no connected source, return a clear setup error and no fake playlist.
- `POST /api/conversation` body `ListeningRequest` → `ListeningResponse`, owner-protected/no-store. 1–12 role=user/assistant messages, ≤800 chars each, last message nonempty user; ≤16KB body. Written conversation follows listener language, separate from chosen hosting/TTS language. Optional context carries a previous direction prompt and ≤12 trackIds; server rehydrates metadata from Store, never trusts browser-supplied song names. Returns updated direction/context for refinements and reference to previous suggestions; default6 or user count≤12, exact point-song/studio-original preference, confirmed order preserved. Uses the same configured model to clarify or derive at most2 music searches/one exact owner playlist, checks actual full-playback rights, then validates ≤12 unique IDs against those candidates. Returns reply/tracks/warnings and optional ProgrammeRequest proposal; NEVER mutates current queue/playback/history or synthesizes speech. Only explicit frontend acceptance calls /api/programme, rechecking rights. Missing/failed/invalid model gives honest503/502, not fake chatbot fallback. One in-flight consultation; durable12 requests/5min; model/provider calls remain bounded,95s elapsed stage budget,frontend135s. UI retains≤30 turns in volatile page memory, sends latest≤11, clears on logout/disconnect; no localStorage, chat database or logs. Conversation/context and selected catalogue metadata go to the owner's configured model, not to Tavily or a new service.
- `POST /api/player/roaming` `{enabled:boolean}` → PlayerActionResponse. Owner-protected; valid only for a programme with stored playlist source. New playlist UI defaults checked; existing/explicit-track programmes are not silently upgraded. Near last3 items starts one deduplicated refill without interrupting current audio; models/rights stay bounded. Seen IDs avoid repeats in this run, source pagination100, max1000 chosen IDs per run; exhaustion/failure disables with explanation, never cycles or changes sources. Queue trims to2 prior tracks plus bounded upcoming items. Late refill invalidated by clear/replacement/toggle/shutdown; pause revision stays authoritative. No physical background guarantee or external discovery implication.
- `GET /api/now` → `NowPlayingState`; `GET /api/queue` → `QueueResponse`, protected.
- `POST /api/player/play` `PlayRequest`; `POST /api/player/pause`; `POST /api/player/next`; `POST /api/player/previous` → `PlayerActionResponse`, protected. Next/previous returns resolved actual track and its chosen-language DJ segment when available.
- `POST /api/feedback` `FeedbackRequest` → `{ saved: true }`, protected. Skipping is NOT a permanent dislike.
- `GET /api/history` → `HistoryResponse`, protected.
- `GET /api/audio/:id` streams cached generated DJ audio; strict identifier/path handling and authentication. Track audio URLs may be safely proxied to the same origin if needed; never accept arbitrary user-supplied proxy URLs.

Endpoints may be extended by agreement, not by racing edits to shared types. If a worker needs a contract/type change, return the exact requested change to Iris.

## Playback contract

The frontend must use an actual HTML audio element: real currentTime/duration, ended/error/pause/play events, honour user pause, and surface autoplay rejection. No ticking simulated progress. Play optional prepared DJ audio, then the current song, then advance the queue. Preload/prefetch where useful without playing before user activation. Media Session controls refer to actual audio state. Volume ducking/transition should be modest; avoid a large sound burst at DJ/song boundaries. Background playback on the physical Xiaomi is not proved by desktop emulation.

## Credentials and runtime

Backend reads application-owned env configuration only: use documented `EMILY_*` names for owner auth, private data directory, NetEase API base, OpenAI-compatible model base/key/name, and TTS execution. Do not inspect Hermes `.env`, Codex auth, other profiles, Windows credentials, Telegram bot credentials or unrelated system state. Parent supplies real runtime bindings later. Store private app state in SQLite (Node builtin available here); protect/restrict credential storage and never commit it.

Edge TTS is already exercised on this host via `uvx --from edge-tts edge-tts`; actual MP3 generation and decoding succeeded. The current default is `zh-CN-XiaoxiaoNeural`; `zh-CN-XiaoyiNeural` is optional Mandarin, the seven previous English female voices remain available. Verify female metadata/availability; a real decode check is not subjective human listening. Use an allowlisted voice, bounded text, execFile argument arrays (not a shell command), caching, timeout and honest failure state. No fake provider responses. Model hosting copy follows the voice language, natural concise Mandarin by default, not a literal translation or invented artist biographies. Optional English still rejects non-Latin spoken names; Chinese may use original catalogue names. Han/script checks supplement prompts, not full language/fact recognition. Old intro/audio references are invalidated on migration, queue/authorization/history retained. Hosting scroll is an 8px/sec reading aid, not word/sentence audio synchronization. Lyrics use actual media position/seek, plain text remains untimed.
